# System Design

Use this skill to turn a system problem into a clear, reviewable design before
implementation decisions are made.

1. State the user goals, constraints, and success measures.
2. Separate functional requirements from quality attributes and assumptions.
3. Name important actors, inputs, outputs, and system boundaries.
4. Sketch the high-level components and the responsibilities of each.
5. Trace the main data and control flows across those components.
6. Identify interfaces, ownership, and failure boundaries.
7. Deepen the parts with the highest risk, cost, or uncertainty.
8. Explain data models, consistency needs, and lifecycle where relevant.
9. Estimate scale using stated workload assumptions rather than invented facts.
10. Address availability, latency, durability, security, and recovery needs.
11. Identify bottlenecks, single points of failure, and capacity limits.
12. Compare credible alternatives against the stated requirements.
13. Record trade-offs, rejected options, and consequences of the chosen design.
14. List open questions, dependencies, and decisions needing confirmation.
15. Present the result so a reviewer can trace every major choice to a need.

Do not present assumptions, scale estimates, or guarantees as verified facts.
