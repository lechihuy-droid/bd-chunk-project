# Documentation

Use this skill to prepare documentation that helps a specific reader complete a
task, understand a decision, or respond safely to a situation.

1. Identify the intended reader and the decision or task they face.
2. State the document purpose and what it does not cover.
3. Lead with the information the reader needs first, not project history.
4. Organize content around reader questions and the order work is understood.
5. Use precise terms consistently and define unavoidable domain language.
6. Explain concepts before relying on them in procedures or examples.
7. Prefer concrete, representative examples over abstract claims.
8. Distinguish required actions, optional guidance, warnings, and context.
9. For API documentation, cover inputs, outputs, errors, limits, and examples.
10. For runbooks, clarify triggers, checks, decisions, escalation, and recovery.
11. For architecture material, explain boundaries, flows, responsibilities, and
    trade-offs.
12. For onboarding material, give newcomers a useful mental model and next
    learning steps.
13. Remove duplication, stale claims, and detail that does not serve the reader.
14. Surface assumptions, ownership, and areas that need validation.
15. End with the next decision, action, or source of clarification.

Do not state procedures, ownership, or system behaviour as certain without support.
