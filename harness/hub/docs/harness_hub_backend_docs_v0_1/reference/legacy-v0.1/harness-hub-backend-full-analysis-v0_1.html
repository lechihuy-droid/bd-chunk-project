2. Phạm vi và cách diễn giải tài liệu nguồn

Bộ tài liệu có hai tầng chất lượng khác nhau. Hai tài liệu 00–02 bản 0.2 đã bổ sung governance và distributed-system principles khá sâu. Các tài liệu 03–16 vẫn là v0.1 ngắn, nhiều file mang nhãn Basic/Detailed Design nhưng chưa đủ chi tiết để code. Bản System Architect Review xác nhận verdict: architecture baseline only.

Tài liệu nguồn giả định
  • Nhiều user/workspace/tenant.
  • PostgreSQL + durable queue + object storage.
  • API/CLI executor worker pool.
  • At-least-once + transactional outbox.
  • Workflow graph song song, retry, recovery.
  • Production security, SLO, HA/DR.
Hub hiện tại
  • Local single-user command center.
  • File-backed JSON/JSONL/YAML.
  • In-process synchronous execution + SSE.
  • Append-only log nhưng chưa delivery guarantee.
  • Linear workflow + child runs + approval.
  • Boundary/governance local, chưa production tenancy.

Do đó, “áp dụng” không đồng nghĩa copy toàn bộ deployment topology. Mỗi yêu cầu được phân thành:

  • Adopt now: nguyên tắc/contract cần đúng ngay cả ở local runtime.
  • Translate: giữ semantics nhưng dùng file-backed implementation.
  • Defer: chỉ triển khai khi requirement multi-user/production xuất hiện.

5. Gap analysis chi tiết

5.1 Workflow definition

Workflow hiện yêu cầu id/nodes/edges/stop, hỗ trợ node agent và validate, bắt buộc đúng một linear chain. Đây là scope tốt cho v1; vấn đề không phải thiếu feature mà là schema chỉ tồn tại trong Python validation.

Nếu UI, API và runtime tiếp tục suy ra schema từ code, mỗi thay đổi field có thể tạo drift. Cần JSON Schema v1 làm contract, còn Python validator giữ semantic checks như template reference và graph order.
  • Thêm schema_version: "1.0", definition hash và compatibility rule.
  • Pin exact workflow source/hash vào run metadata khi start.
  • Giữ linear chain; branch/fan-out là schema major/minor riêng sau khi chốt join/error semantics.
  • Save dùng expected hash/ETag để tránh tab cũ ghi đè workflow mới.

5.2 Runtime state machine

update_run_state hiện merge dict rồi ghi file. Bất kỳ caller nào có thể đặt status; không có bảng transition trung tâm. Target local v1:

Node/attempt state cần tách khỏi metadata.node_index. Mỗi provider call tạo Attempt với attempt_no, execution_id, timestamps, provider/model, status, usage và error. Điều này mở khóa retry, recovery, audit và artifact provenance.

5.3 Command, event và persistence

JSONL hiện hữu có thể tiếp tục dùng, nhưng contract phải trung thực với guarantee local:

  • Mỗi event có schema_version, sequence tăng theo run, correlation_id, causation_id và actor.
  • Mỗi state-changing command có command_id, idempotency key, request hash và expected run version.
  • Cùng key + cùng hash trả lại kết quả cũ; cùng key + khác hash trả conflict.
  • State file chứa version; write dùng compare-before-replace trong lock per-run.
  • State + event chưa atomic hoàn toàn trên filesystem: dùng per-run journal/commit record; không gọi đây là transactional outbox.
  • Tách runtime events dùng cho replay khỏi audit records dùng cho approval, policy denial và sensitive actions.

5.4 Executor boundary

Hiện tại workflow_exec.py gọi get_provider(...).stream_chat cho cả parent và child. Refactor nên giữ provider modules nguyên vẹn, thêm một port nhỏ:

ExecutionRequest
  contract_version, execution_id, idempotency_key
  run_id, node_id, attempt_no
  agent/profile provenance, provider/model
  messages/input refs, deadline, token/cost limits
  permission + data classification

ExecutionEvent
  started | output_delta | reasoning_delta | usage | completed | failed

ExecutionResult
  status, output refs/partial output, usage
  provider request/session id, finish reason
  normalized error category/code/retry_after

Transport retry thuộc adapter; workflow retry thuộc runtime. Provider adapter không được tự chạy arbitrary tool. CLI wrappers phục vụ chat hiện tại không tự động trở thành CLI Executor.

5.5 Artifact lifecycle

write_node_artifact đang ghi {node_id}.md, nên rerun/retry có thể overwrite bằng chứng cũ. Local filesystem đủ để đạt semantics tốt hơn:

runtime/runs/{run_id}/artifacts/
  index.json
  {artifact_id}/
    v0001/
      content.md
      manifest.json
    v0002/
      content.md
      manifest.json

Manifest cần checksum, media type, size, producer run/node/attempt, workflow/agent/skill hashes, input refs, parent version, review result và timestamps. Content/version đã publish không update; archive chỉ đổi logical status trong index.

5.6 Review và human task

Hub hiện gộp ba khái niệm: deterministic validation failure, approval gate và interrupt. Cần chuẩn hóa:

  • ValidationResult: deterministic pass/fail + violations.
  • ReviewResult: GO | NO_GO_REPAIRABLE | NO_GO_BLOCKING | NEED_USER_DECISION + issues.
  • HumanTask: pending/resolved/expired/cancelled, actor, decision, reason, before/after version.

Reviewer chỉ trả verdict; runtime áp transition. Model Orchestrator chưa cần trong v1 nếu routing deterministic đủ dùng.

5.7 API contract

server.py có nhiều endpoint hơn file 11, nhưng body chủ yếu là dict[str, object]. Thứ tự đúng là xuất OpenAPI hiện trạng, đánh dấu endpoint runtime ổn định, sau đó mới tạo /api/v1. Những mutation quan trọng cần:

  • Typed request/response và normalized error: code, message, details, correlation id.
  • Idempotency-Key cho create run/resume/cancel/approve.
  • If-Match hoặc expected version/hash cho save workflow và state commands.
  • 202 + run/execution handle nếu chuyển sang background worker trong tương lai.
  • Giữ compatibility shim cho UI v3 trước khi bỏ endpoint cũ.

5.8 Security và CLI

Hub đã có nhiều control tốt hơn mức tài liệu v0.1: CSRF header/origin guard, traversal checks, signed briefs, risk tiers, denial degradation, bounded child permissions và worktree isolation. Gap còn lại:

  • Policy precedence và hard/soft policy chưa machine-checkable.
  • Run không pin policy version, agent hash, skill hash.
  • Runtime event và artifact chưa có systematic redaction/secret scan.
  • CLI executor chưa có threat model cho network, mounts, process tree, dependency/supply chain và cleanup.
Không triển khai “CLI Executor production” bằng cách tái sử dụng thẳng gitjobs.py. Git job là managed coding workflow; executor contract có lifecycle, isolation và output guarantee khác.

6. Target architecture phù hợp project

Target 1–2 phase tới vẫn là modular monolith, synchronous local execution và filesystem persistence. Boundary logic phải rõ để về sau đổi adapter mà không viết lại runtime.

Không cần tạo hàng loạt service/class theo sơ đồ enterprise. Các boundary trước hết là typed contracts + module tests trong thư mục services.

10. Decision register cần owner duyệt

  1. Persistence horizon: giữ file-backed single-host cho hai phase A–F. Đây là recommendation mặc định.
  2. Workflow v1: giữ linear chain; branch là contract version sau. Đây là recommendation mặc định.
  3. Executor scope: API/provider adapter trước; CLI executor chỉ sau threat model. Đây là recommendation mặc định.
  4. API compatibility: thêm typed /api/v1 dần, giữ endpoint UI hiện tại đến khi migration xong.
  5. Source of truth: approved contracts > runtime design > API docs > implementation plan > code; khác biệt phải có ADR/change note.
Go/no-go: GO cho Phase A (contract baseline) sau khi owner chấp nhận ba recommendation mặc định đầu tiên. NO-GO cho database migration, parallel graph và CLI sandbox trong cùng đợt.
