## Ket luan ngan

LangGraph cung cap mot bo concept rat phu hop voi ke hoach Super Agent Harness cho Harness Hub:

1. **StateGraph**: workflow nen la state machine ro rang, node tra ve partial state update.
2. **Reducers**: state update phai co merge semantics, khong de node ghi de tuy tien.
3. **Checkpointer**: thread/run can checkpoint de resume, replay, HITL, failure recovery.
4. **Store**: long-term memory tach khoi checkpoint ngan han.
5. **Interrupt/resume**: HITL nen la primitive runtime, khong phai text convention trong prompt.
6. **Streaming modes**: UI nen nhan node updates, messages/tokens, custom events, debug events rieng.
7. **Subgraphs / Send / Command**: co pattern chuan cho dynamic worker, routing va subagent delegation.
8. **Agent Server model**: assistants, threads, runs, task queue la vocabulary tot cho Hub API.

Verdict: **Use LangGraph as architecture reference now, not as required dependency in first PR.** Hub nen implement file-first runtime substrate tuong thich ve concept. Chi them `langgraph` dependency sau khi co state/event/checkpoint schema va can graph executor thuc su.

## Nhung concept nen apply vao Hub

### 1. StateGraph -> Hub RuntimeGraph

LangGraph `StateGraph` gom state schema, nodes, edges va compile thanh executable graph. Hub khong can implement full graph engine ngay, nhung nen thiet ke runtime theo cung huong:

```
RunRequest
  -> RuntimeState
  -> Node execution
  -> Partial state update
  -> Reducer merge
  -> Checkpoint/event append
  -> Next node / interrupt / finish
```

De xuat schema toi thieu:

```json
{
  "run_id": "run-...",
  "thread_id": "thread-...",
  "status": "queued|running|interrupted|succeeded|failed|cancelled",
  "messages": [],
  "artifacts": [],
  "tool_calls": [],
  "child_runs": [],
  "interrupts": [],
  "usage": {},
  "metadata": {}
}
```

Hub nen co reducer ro:

| Field | Reducer |
|---|---|
| `messages` | append by id / replace same id |
| `artifacts` | append unique path/id |
| `tool_calls` | append immutable |
| `child_runs` | append/update by child run id |
| `interrupts` | append pending, resolve by interrupt id |
| `usage` | numeric sum by model/source |
| `metadata` | shallow merge |

### 2. Persistence: checkpoint va event log phai tach nhau

LangGraph tach:

- checkpointer: snapshots cua graph/thread state
- store: long-term memory
- event stream: progress/output cua run

Apply vao Hub:

```
harness/hub/runtime/
|- threads/<thread_id>/
|  |- state.json
|  |- checkpoints/
|  |  `- <checkpoint_id>.json
|  |- uploads/
|  |- workspace/
|  `- outputs/
|- runs/<run_id>/
|  |- run.json
|  |- events.jsonl
|  |- artifacts/
|  `- usage.json
`- store/
   |- memory.jsonl
   `- skill_usage.jsonl
```

`state.json` la latest materialized state. `checkpoints/*.json` la snapshots de resume/time-travel. `events.jsonl` la audit/stream log, khong thay the checkpoint.

### 3. Interrupt/resume -> Hub HITL primitive

LangGraph `interrupt()` tam dung execution va luu state. Resume dua payload quay lai node dang cho. Important rules tu docs:

- interrupt payload nen JSON-serializable
- side effects truoc interrupt phai idempotent
- khong reorder multiple interrupts trong cung node
- resume can stable thread id/checkpointer

Apply vao Hub:

Endpoint:

| Endpoint | Vai tro |
|---|---|
| `POST /api/agent/runs/{run_id}/interrupts/{interrupt_id}/resume` | resume bang human payload |
| `POST /api/agent/runs/{run_id}/interrupts/{interrupt_id}/reject` | reject / stop / feed back |
| `PATCH /api/agent/runs/{run_id}/state` | edit state co audit, phase sau |

Event:

```json
{
  "type": "interrupt",
  "run_id": "run-...",
  "interrupt_id": "i-...",
  "reason": "approval_required",
  "payload": {
    "tool_name": "write_file",
    "tool_input": {"path": "harness/hub/web/app.js"},
    "choices": ["approve", "reject", "edit"]
  }
}
```

This maps directly to Hub governance/risk approval. Khong nen tiep tuc chi dung "blocked" text trong chat.

### 4. Streaming modes -> Hub SSE event taxonomy

LangGraph tach streaming thanh nhieu loai. Hub hien co `/api/chat` stream delta/reasoning/done/error; agent runtime nen rich hon.

De xuat:

| LangGraph-ish mode | Hub event | Noi dung |
|---|---|---|
| `messages` | `token` / `assistant_delta` | token/model output |
| `updates` | `node_update` | node done + partial state keys |
| `values` | `state_snapshot` | full/partial latest state |
| `custom` | `artifact` / `tool_result` / `child_run` | domain event |
| `debug` | `debug` | internal trace, only dev mode |
| interrupt stream | `interrupt` | HITL pending |

This will make `#/workspace` useful: left panel run tree, center messages, right panel artifacts/context can all subscribe to same run stream.

### 5. Send/Command -> dynamic workers va routing

LangGraph `Send` phu hop orchestrator-worker: mot planner tao list sections/tasks, roi spawn workers song song. `Command` gom state update + goto/resume/routing.

Apply vao Hub:

- Phase 1: do not implement generic graph.
- Phase 2: implement deterministic "node command" result:

```json
{
  "update": {"artifacts": ["..."]},
  "goto": "review",
  "spawn": [
    {"agent": "reviewer", "objective": "..."},
    {"agent": "tester", "objective": "..."}
  ]
}
```

- Phase 3: translate `spawn` to managed child jobs.
- Later: map this to actual LangGraph `Send`/`Command` if dependency is adopted.

### 6. Subgraphs -> child runtime boundaries

LangGraph docs warn about stateful subgraphs, inherited checkpointers, per-thread persistence, checkpoint conflicts when parallel calls share state.

Apply vao Hub:

- Default child subagent is **stateless relative to parent**, except explicit child task packet.
- Child gets scoped input and writes structured result artifact.
- Parent merges result using reducer.
- If child needs persistent memory, create child `thread_id` explicitly.
- Prevent parallel writes to same checkpoint/artifact path.

This matches DeerFlow's "subagent chain ngan va co dinh" conclusion.

### 7. Agent Server vocabulary -> Hub API naming

LangSmith Agent Server uses:

- Assistants: configured graph/agent blueprint
- Threads: conversation/state container
- Runs: one execution
- Task queue: asynchronous execution
- Persistence: core resource data + checkpoints + store

Apply vao Hub:

| LangGraph Server | Hub name | Apply |
|---|---|---|
| Assistant | Agent profile | `GET /api/agents` |
| Thread | Thread | `GET /api/threads/{id}` |
| Run | Agent run | `POST /api/agent/runs` |
| Task queue | Job queue | reuse `gitjobs`/new runtime queue |
| Checkpoint | Runtime checkpoint | file-first JSON |
| Store | Memory/skill store | `.codex/memories` + Hub store |

Do not clone LangSmith Agent Server now. It brings Postgres/Redis/deploy model that is too heavy for current Hub.

Scope:

- Reducer functions.
- File-backed state + checkpoints.
- JSONL event append/read.
- Interrupt model + resume payload schema.
- API read-only plus resume stub:
  - `GET /api/agent/runs`
  - `GET /api/agent/runs/{run_id}`
  - `GET /api/agent/runs/{run_id}/events`
  - `POST /api/agent/runs/{run_id}/interrupts/{interrupt_id}/resume`

No LLM/tool execution yet.

### Revised Phase 2 - Lead runtime without generic graph engine

Add deterministic node pipeline:

1. `prepare_context`
2. `plan`
3. `act`
4. `review`
5. `finalize`

Each node returns `{update, goto, interrupts, spawn}` and state is merged through reducers. This gives most LangGraph benefits without adding dependency.

### Revised Phase 3 - Managed child workers

- Implement `spawn` -> child run via Hub job substrate.
- Parent event stream relays child events.
- Child result artifacts merge into parent.
- Max concurrency and timeout from config.

### Revised Phase 4 - Optional LangGraph adapter

Only after Phase 1-3:

- Add optional `langgraph` dependency.
- Implement adapter that compiles Hub node functions into `StateGraph`.
- Keep Hub file/event schema as source of truth.
- Do not make LangSmith/Agent Server mandatory.

## Implementation notes for Codex

- Keep file-first, no DB in first PR.
- Tests must not call real LLM APIs.
- Store event log as JSONL, one object per line, append-only.
- Use `thread_id`, `run_id`, `checkpoint_id`, `interrupt_id` as stable IDs.
- Every state mutation should write event + checkpoint or be explicitly marked transient.
- Any side effect before HITL interrupt must be idempotent or deferred until after approval.
- The UI should consume events, not scrape final state repeatedly.

## Final recommendation

The DeerFlow review says "port DeerFlow boundaries, not DeerFlow stack." LangGraph adds the sharper technical version:

**Build a LangGraph-compatible runtime substrate first: typed state, reducers, checkpoints, interrupts, streaming event taxonomy, and run/thread vocabulary.**

Then choose executor later. If Hub-native pipeline is enough, keep it. If workflows become complex enough to need graph compilation, plug LangGraph in as an adapter, not as the architecture owner.
