## Ket luan ngan

DeerFlow co tai lieu ro ve cau truc Super Agent Harness. Diem dang hoc nhat khong phai LangGraph, ma la cach no chia runtime thanh cac lop on dinh:

1. Gateway API tach khoi agent runtime.
2. Lead Agent la entrypoint duy nhat.
3. Middleware chain xu ly cac concern ngang: thread data, uploads, sandbox, guardrail, summarization, memory, clarification, loop/subagent limit.
4. Subagent duoc goi qua `task()` va backend quan ly lifecycle, timeout, polling, streaming.
5. Moi thread co filesystem rieng: workspace, uploads, outputs.
6. Skills load theo progressive disclosure, khong nhan het noi dung skill vao prompt ngay tu dau.
7. Guardrail la pre-tool-call authorization, khong dua toan bo safety vao prompt.
8. Memory la subsystem rieng, duoc inject vao context va cap nhat async.

Ap dung cho Harness Hub: **Go**, nhung theo phase nho. Khong nen import DeerFlow/LangGraph nguyen khoi vao Hub luc nay. Hub hien la FastAPI + vanilla static UI + services co san; nen them "super agent harness core" nhu mot runtime module nho, reuse `gitjobs`, `risk`, `governance`, `usage`, `replay`, `chat`.

## DeerFlow pattern can dung

### 1. Lead Agent la runtime entrypoint

DeerFlow co `make_lead_agent(config)` lam entrypoint. Lead Agent khong chi la chat model; no gom model selection, middleware chain, tools, subagent delegation, system prompt, skills, memory va working directory.

Apply vao Hub:

- Tao khai niem `RunRuntime` hoac `LeadRuntime`, khong nhan UI request roi goi service roi rac.
- Mot request agent run nen di qua cung mot pipeline:
  `request -> thread data -> policy/guardrail -> model/tool runtime -> stream events -> artifacts/usage/replay`.
- API moi nen song rieng voi chat hien tai, vi `#/chat` va `#/workspace` dang on dinh.

De xuat endpoint:

| Endpoint | Vai tro |
|---|---|
| `GET /api/agents` | list profile agent co the chay |
| `GET /api/threads/{thread_id}` | doc thread state va artifacts |
| `POST /api/agent/runs` | tao lead-agent run |
| `GET /api/agent/runs/{run_id}/stream` | SSE progress/events |
| `POST /api/agent/runs/{run_id}/cancel` | cancel run |

### 2. Middleware chain co thu tu co dinh

DeerFlow tai lieu hoa ro middleware chain va nhan manh day khong phai onion model. Cac middleware khong can doi xung; moi cai chi dung hook can thiet.

Apply vao Hub:

- Khong can copy LangChain `AgentMiddleware`.
- Nen tao pipeline nhe trong Python voi cac buoc co thu tu ro, test duoc.
- Ban dau dung sync/async function + dataclass context la du.

Thu tu Hub nen bat dau:

| Thu tu | Middleware Hub | Ly do |
|---:|---|---|
| 1 | `ThreadData` | Tao `workspace/uploads/outputs/artifacts` cho thread/run. |
| 2 | `InputFiles` | Chuan hoa uploads/file references vao run context. |
| 3 | `Guardrail` | Kiem tra tool/command/path/network truoc khi execute. |
| 4 | `Budget` | Gioi han time/steps/tokens/subagents. |
| 5 | `SkillContext` | Load metadata truoc, full skill chi khi selected. |
| 6 | `ToolRuntime` | Cung cap tool registry: read/write, diff, bash, job, chat. |
| 7 | `LoopDetection` | Canh bao lap tool call, repeated failure. |
| 8 | `Usage` | Ghi token/calls/run usage vao log hien co. |
| 9 | `Memory` | Inject va cap nhat memory sau run, khong block critical path. |
| 10 | `Clarification/HITL` | Intercept can hoi user hoac can approval. |

Khac DeerFlow: Hub da co `governance`, `risk`, `usage`, `replay`, `gitjobs`; nen pipeline moi nen wrap cac service nay thay vi viet lai.

### 3. Thread filesystem rieng

DeerFlow dung per-thread directories: workspace, uploads, outputs, artifacts; sandbox virtual path map ve physical path.

Apply vao Hub:

```
harness/hub/runtime/
|- threads/
|  `- <thread_id>/
|     |- state.json
|     |- uploads/
|     |- workspace/
|     |- outputs/
|     `- artifacts/
`- runs/
   `- <run_id>/
      |- events.jsonl
      |- tool_calls.jsonl
      |- usage.json
      `- final.md
```

Luu y: Hub hien co `harness/runs` va `harness/hub/jobs`. Khong nen tron runtime thread state vao run benchmark cu. Tao namespace rieng `harness/hub/runtime` de tranh pha cac parser/report hien co.

### 4. Subagent qua `task()` nhung backend quan ly lifecycle

DeerFlow da sua `task()` de LLM khong tu poll `task_status`. Backend start async, backend poll, tool call block den khi co result hoac timeout. Day la pattern tot.

Apply vao Hub:

- Lead agent co tool noi bo `task(subagent_type, prompt, description, scope)`.
- Tool nay khong expose polling cho model.
- Backend tao child job, stream event ve parent, gom result vao artifact.
- Child job nen reuse `gitjobs`/Codex runner thay vi mo mot executor moi.

De xuat child task packet:

```json
{
  "parent_run_id": "run-...",
  "thread_id": "thread-...",
  "subagent_type": "reviewer",
  "objective": "Review changed UI files against DESIGN.md",
  "allowed_paths": ["harness/hub/web"],
  "allowed_tools": ["read", "test", "diff"],
  "skills": ["opus-design-reviewer"],
  "budget": {"seconds": 900, "steps": 30},
  "return_contract": "write findings to artifacts/claims.jsonl"
}
```

Default guardrails:

- Max 3 child tasks per parent run.
- Timeout 15 minutes per child.
- Child cannot extend its own tool/path scope.
- Child output must be structured artifact, not only chat text.
- Parent synthesizes child results; child does not write final user response directly.

### 5. Main agent va subagent khac middleware

DeerFlow RFC noi main agent co middleware chain day du, subagent chain ngan va co dinh. Day la diem quan trong.

Apply vao Hub:

| Concern | Lead runtime | Child runtime |
|---|---:|---:|
| ThreadData | Yes | Yes |
| Uploads | Yes | No, chi doc scoped files |
| Guardrail | Yes | Yes |
| ToolErrorHandling | Yes | Yes |
| Summarization | Yes | No phase dau |
| Memory | Yes | No phase dau |
| SubagentLimit | Yes | No |
| Clarification/HITL | Yes | No, child fail with blocked status |

Ly do: child runtime phai predictable. Neu child cung co memory/summarization/clarification day du, debug se rat kho.

### 6. Skills progressive disclosure

DeerFlow coi skill la capability package, load metadata truoc, full `SKILL.md` chi khi task can. Day hop voi Codex skills hien tai va voi Hub.

Apply vao Hub:

```
harness/hub/skills_index.json
or
harness/hub/runtime/skills/index.json
```

Index nen co:

| Field | Y nghia |
|---|---|
| `id` | stable skill id |
| `name` | display name |
| `description` | metadata ngan |
| `source_path` | path skill package |
| `allowed_tools` | tool/tool group skill can |
| `risk_tier` | low/medium/high/destructive |
| `enabled` | co expose cho agent khong |

Phase dau khong can build skill installer. Chi can endpoint read-only:

- `GET /api/skills`
- `GET /api/skills/{id}`
- `GET /api/skills/{id}/usage`

### 7. Guardrail la provider protocol, khong chi prompt

DeerFlow guardrail chay truoc tool call, co provider interface `evaluate(request) -> decision`, co allow/deny reasons va runtime attribution.

Apply vao Hub:

Hub da co `risk_tiers.json`, `services/risk.py`, `services/governance.py`, `services/boundary.py`. Nen them mot adapter:

```
GuardrailRequest:
  tool_name
  tool_input
  agent_id
  thread_id
  run_id
  is_subagent
  user_id
  risk_tier

GuardrailDecision:
  allow
  reasons
  policy_id
  metadata
```

Khong can OAP Passport phase dau. Built-in allowlist/denylist + existing `risk_tiers.json` la du.

### 8. Memory nen async va co surface rieng

DeerFlow MemoryMiddleware queue conversation de extract memory async. Root README cung nhan manh memory dai han, duplicate skip.

Apply vao Hub:

- Dung memory nhu context support, khong lam blocking dependency cua run.
- Ban dau doc memory tu `C:\Users\HUY\.codex\memories` hoac Hub memory cache, inject vao lead prompt.
- Sau run, tao event `memory_candidate` de user accept/reject, khong auto-write neu chua co rule ro.

Endpoint co the them sau:

- `GET /api/memory`
- `GET /api/memory/candidates`
- `POST /api/memory/candidates/{id}/accept`
- `POST /api/memory/candidates/{id}/reject`

## Nhung thu khong nen copy nguyen

1. **Khong dua Next.js/React vao Hub.** Hub dang vanilla JS, static SPA, khong build step. DeerFlow UI stack khong hop constraint hien tai.
2. **Khong import LangGraph ngay phase dau.** Hub can reliability va control-plane truoc. Neu can graph executor, them adapter sau khi IR va event model da on dinh.
3. **Khong mo sandbox/bash rong.** Hub hien da co job/risk/governance. Bash/terminal phai di qua managed job/subagent runner.
4. **Khong cho subagent tu sinh subagent vong lap.** Lead-only delegation trong phase dau.
5. **Khong auto-mutate skills.** Skills chi read-only; neu can sua skill thi tao proposed diff/job rieng.
6. **Khong tron run benchmark voi agent runtime.** Giu `harness/runs` cho eval/report hien co; tao runtime namespace rieng.

## De xuat implementation theo phase

### Phase 1 - Runtime substrate read-only

Muc tieu: co schema va API doc, chua can agent tu tool-use that.

Files de them:

```
harness/hub/services/runtime_state.py
harness/hub/services/runtime_events.py
harness/hub/services/runtime_guardrails.py
harness/hub/services/runtime_skills.py
harness/hub/tests/test_runtime_state.py
harness/hub/tests/test_runtime_guardrails.py
harness/hub/docs/super-agent-runtime.md
```

Deliverables:

- Dataclass/schema cho `ThreadState`, `RunState`, `RuntimeEvent`, `GuardrailRequest`, `GuardrailDecision`.
- File layout `harness/hub/runtime/...`.
- API read-only: list thread/run/artifacts/events.
- Tests khong goi API model that.

### Phase 2 - Lead runtime around existing chat

Muc tieu: mot lead run co event stream va usage/replay, nhung toolset toi thieu.

Add:

- `POST /api/agent/runs`
- `GET /api/agent/runs/{run_id}/stream`
- Tool registry noi bo: `read_file`, `list_dir`, `write_artifact`, `ask_user_blocked`.
- Guardrail truoc moi tool call.
- UI co the hien trong `#/workspace` as real runs/artifacts thay vi mock dan.

### Phase 3 - Managed subagent via existing gitjobs

Muc tieu: lead runtime goi child Codex job co scope, timeout, artifacts.

Add:

- `task()` backend function, not user-visible polling tool.
- Parent-child relation in run state.
- Child event relay vao parent SSE.
- Max child concurrency 3; timeout 900s default.
- Output contract: `claims.jsonl`, `summary.md`, optional patch/diff.

### Phase 4 - Skills + memory + policy UI

Muc tieu: Hub tro thanh control-plane cho skill/memory/guardrail.

Add:

- Skills index UI.
- Memory candidate accept/reject.
- Guardrail decision log.
- Runtime replay view.
- Skill usage telemetry.

## Suggested first PR scope

Sau khi tham khao LangGraph, PR dau van nen nho nhung phai co du substrate cho durable runtime:

1. Them `harness/hub/docs/super-agent-runtime.md` gom schema, reducer, checkpoint, interrupt va API plan.
2. Them `services/runtime_state.py` voi pure file state manager.
3. Them `services/runtime_reducers.py` de merge partial state updates.
4. Them `services/runtime_checkpoint.py` de ghi latest state + checkpoint snapshots.
5. Them `services/runtime_events.py` append/read `events.jsonl`.
6. Them `services/runtime_interrupts.py` cho HITL interrupt/resume schema.
7. Them endpoint read-only/resume:
   - `GET /api/agent/runs`
   - `GET /api/agent/runs/{run_id}`
   - `GET /api/agent/runs/{run_id}/events`
   - `POST /api/agent/runs/{run_id}/interrupts/{interrupt_id}/resume`
8. Them tests cho reducers, file layout, checkpoint va event append/read.

Khong them LLM/tool execution trong PR dau. Khi state/event substrate on dinh, moi gan chat/tool/subagent vao.

## LangGraph follow-up

Da bo sung review rieng tai `../langgraph/REVIEW-apply-to-hub.md`. Ket luan tu LangGraph:

- Apply concepts: `StateGraph`-style state machine, reducers, checkpoints, interrupts/resume, streaming event taxonomy, assistants/threads/runs vocabulary.
- Khong add dependency `langgraph` ngay phase dau.
- Khong copy LangSmith Agent Server/Redis/Postgres runtime vao Hub luc nay.
- Build Hub-native, file-first runtime substrate truoc; neu sau nay workflow phuc tap thi them LangGraph adapter sau.

## Design decisions khuyen nghi

| Decision | Khuyen nghi |
|---|---|
| Executor | Phase dau khong LangGraph; dung Hub-native runtime pipeline. |
| State | File-first JSON/JSONL, vi Hub da file-oriented va replay-friendly. |
| Agent spawning | Chi lead runtime duoc spawn child. |
| Child runner | Reuse `gitjobs`/Codex managed runner. |
| Guardrail | Provider protocol nho, backed by existing risk/governance. |
| Skills | Read-only index first; progressive disclosure. |
| Memory | Candidate workflow, khong auto-write silently. |
| UI | Reuse `#/workspace`; replace mock artifacts/files gradually. |

## Review verdict

**Go.** DeerFlow la reference tot cho "super agent harness", nhung Harness Hub nen apply theo huong native:

- Giu FastAPI + static SPA.
- Giu existing Hub services lam control-plane.
- Them runtime substrate file-first.
- Them middleware chain va guardrail protocol nho.
- Reuse `gitjobs` cho subagent.
- Dung `#/workspace` lam UI surface de hien threads/runs/artifacts that.

Do not start by porting DeerFlow stack. Start by porting DeerFlow boundaries.
