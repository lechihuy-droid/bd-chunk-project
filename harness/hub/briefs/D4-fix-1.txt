THE BUG (confirmed empirically by review): `gate: approval` fires BEFORE the gated node executes, and the
interrupt payload carries that node's ALREADY-RENDERED prompt. In harness/hub/workflows/code-task.workflow.yaml
the gate is on `brief` (the FIRST node), whose prompt contains only {{objective}} — so:
  - the human is asked to approve before any brief text exists (payload has no brief content), and
  - after resuming that one interrupt, BOTH `brief` AND `implement` run in the same pass —
    `implement` uses the `coder` agent (permission: workspace_write), so code gets written with no human
    ever seeing the actual brief.
This contradicts the file's own header comment and is the exact failure the gate was meant to prevent.
