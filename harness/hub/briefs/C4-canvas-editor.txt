GAP DECISION — `ui:` section convention: no prior convention exists anywhere
in the codebase (checked review-ui.workflow.yaml and workflow.py). Define and
use:
```yaml
ui:
  nodes:
    plan: {x: 40, y: 40}
    act: {x: 240, y: 40}
```
Top-level optional key, sibling of `id`/`nodes`/`edges`/`stop`. Purely
display metadata — never referenced by `validate_workflow`, `build_ir`, or
`workflow_exec.py`. If a node id in `nodes` has no entry under `ui.nodes`,
canvas.js falls back to auto-layout (see step 1). If `ui.nodes` has stale
entries for node ids that no longer exist, drop them silently on next save
(do not error).

TASK:
1. New file `harness/hub/web/canvas.js` (vanilla SVG, NO CDN/libs, same
   IIFE + `window.HubCanvas = {...}` export style as charts.js's
   `window.HubCharts`):
   - `mount(container, model)` where `model` is a plain JS object already
     parsed from the workflow yaml (`{id, nodes: [{id, agent, prompt, gate}],
     edges: [[a,b],...], stop: {...}, ui: {nodes: {...}}}` — parsing the
     yaml text into this shape happens in app.js via the existing
     `POST /api/workflows/validate {yaml_text}` call's echoed-back data, or
     by fetching `GET /api/workflows` and finding the entry by id; canvas.js
     itself never talks to fetch/XHR, it is pure render+interaction).
   - Render: one `<rect>`+`<text>` group per node ("node box") showing id,
     agent name, and a small gate badge (only if `gate === "approval"`,
     styled like an existing `.badge` class per DESIGN.md, do not invent a
     new badge visual). Position from `model.ui.nodes[id].{x,y}` if present;
     else auto-layout as a horizontal chain: walk `edges` in order starting
     from the node with no incoming edge, `x = index * 200`, fixed `y`.
   - Edges: arrow from each node's right edge to the next node's left edge,
     following the chain order in `edges` (sequential only — this schema
     only supports one linear chain, `_walk_chain` in workflow.py rejects
     anything else, so canvas.js never needs to render branching or
     freeform edges).
   - Drag: pointerdown/pointermove/pointerup (or mousedown/mousemove/mouseup
     — your call, no need for pointer capture polish) on a node box updates
     that node's `model.ui.nodes[id].{x,y}` only. This is display metadata,
     never touch `model.nodes`/`model.edges` semantics from a drag.
   - Click node (not drag) -> open a side panel (plain DOM form, can live
     outside the SVG, e.g. an absolutely-positioned `<div>` the mount
     function also renders into `container`): prompt `<textarea>`, agent
     `<select>` (options populated from `GET /api/agents` — canvas.js can
     take agent list as a `mount(container, model, agentList)` third arg
     rather than fetching itself, keep canvas.js fetch-free for testability),
     gate `<select>` with exactly `none`/`approval`. Editing these fields
     mutates the corresponding node in `model.nodes` in place.
   - Add-node button: appends a new node to the end of the chain — new
     unique id (e.g. `node-<n>` incrementing until unused), default
     `agent: agentList[0].id`, default `prompt: "{{<lastNodeId>_output}}"`
     (or `"{{objective}}"` if this is the first node), default `gate: "none"`,
     pushes `[lastNodeId, newId]` onto `model.edges`, positions it at
     `lastNode.x + 200, lastNode.y` (or auto-layout fallback position).
   - Delete-node button (per-node, only enabled on the current chain's last
     node — i.e. the node with no outgoing edge): removes it from
     `model.nodes`, removes any edge pointing to it from `model.edges`.
     Refuse (disable the button, no-op) when only 1 node remains — an empty
     `nodes` list fails `_walk_chain` (no valid start/end), so canvas.js must
     never produce that state client-side either.
   - `mount()` returns an object exposing at least `{getModel(): model}` so
     app.js can pull the current edited state out for the save flow, without
     canvas.js knowing anything about yaml or fetch.

6. Backend route — `harness/hub/server.py`, inside the
   `# --- C2a workflow routes ---` / `# --- end C2a workflow routes ---`
   marker block (alongside `api_workflows`/`api_workflow_validate`, NOT the
   C2b run-routes block which is a different concern):
   ```python
   @app.put("/api/workflows/{workflow_id}")
   def api_workflow_save(workflow_id: str, payload: dict[str, object]) -> dict[str, object]:
       yaml_text = payload.get("yaml_text")
       if not isinstance(yaml_text, str):
           raise HTTPException(status_code=400, detail="yaml_text must be a string")
       try:
           return workflow.save_workflow(workflow_id, yaml_text)
       except FileNotFoundError as exc:
           raise _http_error(exc) from exc
       except ValueError as exc:
           raise HTTPException(status_code=400, detail=str(exc)) from exc
   ```
   (adjust to match whatever `save_workflow`'s actual return/raise shape
   ends up being — this is illustrative, not gospel; if `_http_error` only
   handles `(FileNotFoundError, PermissionError)` per its existing usages,
   follow that exact pattern rather than inventing a new helper.)
